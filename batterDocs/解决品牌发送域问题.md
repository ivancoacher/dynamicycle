<h1>解决品牌发送域问题</h1>

<h2>你将会学到</h2>
<p>了解在 Klaviyo 中设置品牌发送域（也称为专用发送域）时如何诊断验证问题。品牌发送域使您能够发送来自您的品牌的电子邮件，而不是来自 Klaviyo 的共享域。有关设置说明，请访问我们的指南[如何设置品牌发送域](https://help.klaviyo.com/hc/en-us/articles/115000357752)。 Google 和雅虎已宣布新的发件人要求，计划于 2024 年 2 月开始实施。虽然这已经是最佳实践，但设置品牌发送域将成为批量发件人进入 Gmail 收件箱的要求。 Google 将每天向 Google 帐户发送 5000 封或更多电子邮件的人视为“批量发件人”。来自发件人的所有流量都计入 5000 封电子邮件阈值，包括交易电子邮件。详细了解 [Gmail 和 Yahoo 即将推出的发件人要求。](https://www.klaviyo.com/blog/gmail-update)</p>
<h2>开始之前</h2>
<p>在开始以下故障排除步骤之前，请确认您已尝试在 Klaviyo 中验证您的发送域并看到错误。请注意，Klaviyo 在验证后不会自动应用您的域，因为我们希望确保您准备好首先预热您的发送基础设施（如果适用）。验证后，您需要单击<strong><em>*应用域名</strong></em>*。我们还建议给 DNS 传播和清除缓存的时间。此过程可能需要长达 48 小时，具体取决于您的 DNS 提供商。 ## 使用第三方工具进行故障排除</p>
<p>Klaviyo 需要 3 个 CNAME 或 NS 记录用于电子邮件身份验证，以及 1 个 TXT 记录用于域所有权验证。在 Klaviyo 中设置品牌域名时，您会看到根据您的[子域名](https://klaviyo.zendesk.com/hc/en-us/articles/360055457791) 选择显示的类似记录：</p>
<img src="https://klaviyo.zendesk.com/hc/article_attachments/28705664613147" alt="NS 记录" />
<p>设置品牌发送域时，选择<strong>动态</strong>路由方法需要将 NS 记录添加到您的 DNS 提供商，而<strong>静态</strong>路由选项需要 CNAME 记录。 Klaviyo 建议使用 <strong>动态</strong> 路由选项来最好地优化您的发送，但如果您的 DNS 提供商不支持 NS 记录，请考虑使用 <strong>静态</strong> 路由选项。如果您的品牌选择使用二级子域，例如 <strong>example.send.klaviyo.com</strong>，则根域将为 <strong>send.example.com</strong>，发送域将为 <strong>example.send.klaviyo.com</strong>。</p>

<p>根据您是否看到查询返回的值，一些常见错误可能是问题的根源。 ## 如果查询返回值</p>
<p>为了使您的发送域在 Klaviyo 中成功验证，您的查询返回的值必须与 Klaviyo 中显示的值完全匹配。确保您看到的返回值与 Klaviyo 中的值之间没有任何差异。 ### 根域自动附加到值中</p>
<p>一些 DNS 提供商希望附加值末尾有一个句点 (.)。如果没有这段时间，DNS 提供商会假定整个值字段是正在配置的域的子域，并将自动添加根域。例如，如果您输入 <strong>u161779.wl030.sendgrid</strong> （末尾没有句点），这将使值 <strong>u161779.wl030.sendgrid.net.rootdomain.com</strong> 而不仅仅是 <strong>u161779.wl030.sendgrid.net。</strong></p>
<h2>如果查询没有返回值</h2>
<h3>根域在主机名中重复</h3>
<p>我们还建议检查您的 DNS 提供商是否只需要主机名字段中的子域，并自动附加根域。例如，如果您添加 CNAME 记录 <strong>send.domain.com</strong>，它将自动变为 <strong>send.domain.com.domain.com</strong>。相反，您可能只需要在此实例中添加“send”子域，以使记录的主机名成为 <strong>send.domain.com。</strong> 比较您的其他 DNS 记录，看看您是否需要附加它，或者您的提供商是否自动执行此操作。 ### 被代理的记录</p>
<p>如果您的 DNS 提供商允许您代理记录，并且启用此功能，您将在 Klaviyo 中看到品牌域设置问题。 Cloudflare 中通常会发生这种情况，但其他 DNS 提供商也可能发生这种情况。您需要禁用记录的代理，以便它们通过互联网进行解析，这样就可以通过 Klaviyo 中的发送域设置工具来验证它们的存在。在设置过程之后，记录代理需要保持禁用状态，并且电子邮件才能按预期进行身份验证。 ## 其他 DNS 提供商问题</p>
<h3>DNS 提供商不支持 @ 符号</h3>
<p>如果 DNS 提供商不支持符号“@”，则需要将根域设置为站点验证记录的主机名。 “@”符号是根域 (business.com) 的简写，因此您可以根据您的 DNS 提供商支持的内容使用任一选项。 ### DNS 提供商不支持下划线</p>
<p>某些 DNS 提供商不支持 CNAME 记录使用下划线。但是，为了使您的发送域在 Klaviyo 中正常工作，这些下划线是必要的。如果您的 DNS 提供商不支持 CNAME 中的下划线，我们建议您首先联系 DNS 提供商的支持团队，看看他们是否可以为您创建记录。通常，如果您联系 DNS 提供商，他们将能够手动调整您的 CNAME 以包含下划线。如果您的 DNS 提供商最终无法支持下划线，请[考虑使用其他提供商](https://www.hostinger.com/tutorials/how-to-change-domain-nameservers)，因为这些对于您在 Klaviyo 中的域设置是必需的。 ### 根域上已存在 TXT 值</p>
<p>如果您的根域上存在现有 TXT 记录，您可以将 Klaviyo 值附加到现有字段。只要存在 Klaviyo 请求的值，在 Klaviyo 中设置您的品牌域名时，记录就会成功验证。 ## DMARC</p>
<p>为了使电子邮件符合 [DMARC](https://help.klaviyo.com/hc/en-us/articles/4402601857307)，您帐户上的根域需要与电子邮件的发件人地址域保持一致。 例如，如果您使用 <strong>sales@example.com</strong> 作为发件人地址发送电子邮件，其中 example.com 受 DMARC 保护，则您的帐户将需要对从 Klaviyo 发送的所有电子邮件使用品牌发送域（例如 <strong>send.example.com</strong>），以满足 DMARC 身份验证要求。</p>
