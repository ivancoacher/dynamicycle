<h1>如何创建程序（测试版）</h1>

<p>> <strong><em>*Beta 功能。</strong></em>* 从头开始​​创建完全自定义的过程目前处于封闭管理测试阶段。如果您没有看到创建程序的选项，则您的帐户尚不具有测试版访问权限。 ## 你将会学到</p>
<p>如何从头开始构建完全自定义的程序，编写描述和说明，使客户代理在正确的时间使用您的程序，并在购物者看到它之前对其进行测试。本文还介绍了如何自定义客户代理附带的过程。 ## 开始之前</p>
<p>你需要：</p>
<ul>
<li>启用客户代理和测试版访问权限，以创建完全自定义的程序</li>
<li>清楚地了解您的程序应该处理什么——问题的类型、情况或工作流程</li>
<li>您的程序将使用的任何工具 - 客户代理附带的工具或您构建的完全自定义的工具</li>
</ul>
<p>如果您希望客户代理执行特定操作（在系统中查找数据、在另一个平台中采取操作），请首先创建该工具或与您的过程一起创建该工具。 ## 什么是程序</p>
<p><strong>程序</strong><strong>是一种限定范围的功能，可让客户代理处理特定类型的购物者请求。客户代理附带了开箱即用的程序，从头开始创建完全自定义的程序目前处于封闭测试阶段。程序有</strong><strong>标题</strong><strong>、</strong><strong>何时使用此程序</strong><strong>部分（客户代理如何知道此程序应处理给定的请求）和</strong><strong>如何响应</strong>**部分（选择程序后客户代理应如何表现）。您还可以附加工具和内容范围。有关基本概念，请参阅了解客户代理工具一文和了解过程与工具一文。 ## 何时创建完全自定义的过程</p>
<p>在以下情况下构建完全自定义的过程：</p>
<ul>
<li>****客户代理附带的程序不涵盖您的用例**** - 您有客户代理无法立即处理的工作流程或问题类型</li>
<li>****您的企业具有行业特定的行为**** — 专门的规则、独特的产品配置、领域语言</li>
<li>****您想要一个多步骤的自定义流程**** - 例如，测验、引导式故障排除程序或将多个工具链接在一起的工作流程</li>
<li>****您想要使用完全自定义的工具**** - 完全自定义的工具仅在附加到过程时执行某些操作</li>
</ul>
<h2>设置</h2>
<h3>1. 打开程序页面</h3>
<p>导航至<strong><em>*客户代理 > 程序</strong><strong>，然后单击</strong><strong>创建程序</strong></em>*。 ### 2. 添加标题</p>
<p>简短的标识符，例如“尺寸指南”或“保修索赔”。标题主要供您参考和组织 - 它不用于决定程序何时触发。 ### 3. 写下“何时使用此程序”</p>
<p><strong><em>*何时使用此过程</strong><strong> 告诉客户代理的路由器您的过程何时应处理请求。使用自然语言。具体说明此过程处理的内容以及（如果有用）它</strong>不<strong>处理的内容。包含示例购物者问题有助于路由器识别匹配的意图。 </strong><strong>好的例子：</strong></em>*</p>
<p><strong>尺寸指南程序：</strong></p>
<p>> 当购物者询问寻找合适的服装或鞋类尺码时，请使用此程序 - 包括尺码表、合身建议和尺码更换。示例问题：“这件衣服我应该买多大尺码的？”、“你的鞋子偏小吗？”、“我怎么知道这件衣服合脚吗？”、“我可以换一个不同尺码的吗？”。请勿将此程序用于解决缺货问题；这些将用于一般支持。 <strong><em>*模糊的例子（避免）：</strong></em>*</p>
<p>> 有关尺码和其他产品信息的问题。模糊版本不会告诉路由器何时选择此程序而不是其他程序，也不会显示任何应匹配的具体客户问题。 ### 4.写下“如何回应”</p>
<p><strong><em>*如何回应</strong></em>* 告诉客户代理在选择您的程序后如何行事。将其视为一个简短的剧本。该字段是一个富文本编辑器 - 您可以自由键入，也可以键入“/”来插入特定元素（标题、列表、工具或切换操作）。好的“如何回应”内容：</p>
<ul>
<li>特定于该程序处理的内容并限定其范围</li>
<li>描述客户代理应如何处理请求 - 分为清晰的主题部分（未编号的步骤）</li>
<li>通过“/”在每个工具应该运行的位置插入工具</li>
<li>在升级适用的情况下通过“/”插入切换操作</li>
<li>指出当数据丢失或请求超出范围时该怎么做</li>
</ul>
<p>保持简洁。冗长而曲折的指导对绩效的伤害大于其帮助。 <strong><em>*您可以通过</strong><strong>`/`</strong><strong>插入什么：</strong></em>*</p>
<ul>
<li>****格式**** — 文本、标题 1/2/3、项目符号列表、编号列表。使用它们来构建说明，以便于阅读和编辑。 - ****动作**** — 两个切换动作：</li>
<li>**提供交接** — 客户代理为购物者提供在交接之前与人工联系的选项。 - **立即移交** — 客户代理无需询问即可移交。 - ****工具**** — 此过程附加的每个工具都显示在此处。在您希望客户代理使用它的位置插入内联工具。 ### 5.附加工具（可选）</li>
</ul>
<p>如果您的过程需要获取数据或采取操作，请附加它应该使用的工具。一个过程可以使用多个工具。 “如何回应”部分应告诉客户代理何时使用哪种工具。请参阅如何创建工具文章来构建您自己的工具。 ### 6.附加内容范围（可选）</p>
<p>如果您的程序应仅使用特定内容（例如，仅使用专用的大小指南而不是整个知识库），请设置内容范围。将此留空以使用所有可用内容。 ### 7. 在操场上测试</p>
<p>单击<strong><em>*测试</strong></em>*打开playground。发送通常会路由到您的过程的测试消息，并检查：</p>
<ul>
<li>****路由器行为**** — 客户代理实际上是否为测试消息选择了您的程序？如果没有，“何时使用此程序”需要研究。 - ****响应行为**** — 客户代理是否遵循您在“如何响应”中描述的步骤？ - ****工具**** — 如果程序应该使用工具，是吗？有正确的参数吗？ - ****响应质量**** — 输出是购物者所期望的吗？根据您所看到的情况反复讨论“何时使用此程序”和“如何应对”。 ### 8.启用程序</li>
</ul>
<p>当您对游乐场测试感到满意时，启用该过程。它将开始处理与“何时使用此程序”匹配的实时对话。</p>
<h2>写一篇好的“何时使用此过程”</h2>
<p>这是程序中最重要的字段。路由器使用它（并且仅使用它）来决定您的过程何时应处理请求。一个很好的“何时使用此程序”：</p>
<ul>
<li>****用简单语言描述程序处理的内容****</li>
<li>****足够具体****，路由器不会为不相关的请求选择它</li>
<li>****足够广泛****，路由器会选择它来处理它应该处理的所有请求</li>
<li>****在有用处指出边缘情况**** - 此过程**不**处理的内容</li>
</ul>
<p>通过游乐场测试进行迭代。如果您的程序在不应该触发的时候触发，请收紧“何时使用此程序”。如果它在应该触发的时候没有触发，请扩大它或添加示例。 ## 写一个好的“如何回应”</p>
<p>这告诉客户代理在选择程序后如何处理请求。好的“如何回应”内容：</p>
<ul>
<li>****范围****是这个程序的作用——不要试图涵盖所有内容</li>
<li>****使用标题将响应分成清晰的主题部分****（未编号的步骤）</li>
<li>****在每个工具应运行的位置内嵌插入工具**** — 输入“/”并从菜单中选择该工具</li>
<li>****插入内联移交操作**** — 输入 `/` 并选择 **提供移交** 或 **立即移交**（如果适用）</li>
<li>****处理后备案例**** —“如果数据丢失，请道歉并提出移交”</li>
<li>****显示良好回应的形式**** — 格式、语气、包含内容</li>
</ul>
<p><strong><em>*示例（订单跟踪程序的“如何响应”）：</strong></em>*</p>
<p>> <strong><em>*识别购物者并订购</strong></em>*</p>
<p>> 如果购物者未登录，请告知他们需要登录才能找到订单。登录后，使用电子邮件或电话号码找到客户的个人资料，然后使用 /Get Profile 查找他们最近的订单。 > <strong><em>*检查发货状态</strong></em>*</p>
<p>> 使用 /Order Status 检索特定订单的实时状态、跟踪 URL 和预计交货日期。 > <strong><em>*提供更新</strong></em>*</p>
<p>> 清楚地传达当前状态（例如，正在处理、已发货、已交付）。如果发货，请务必提供可点击的跟踪链接。 ## 定制现有程序</p>
<p>您可以从“程序”页面禁用客户代理附带的任何程序 - 如果您不希望客户代理处理特定类型的请求，这很有用。编辑现有程序（更改指令、交换工具）即将推出。当它发布时，本文将介绍该流程。 ## 故障排除</p>
<p><strong><em>*症状：</strong><strong> 该过程从未被使用。 </strong><strong>可能的原因：</strong><strong>“何时使用此过程”太模糊，或者路由器无法识别匹配的请求。 </strong><strong>修复：</strong><strong> 重写“何时使用此过程”以更具体地说明该过程处理的内容。添加示例请求类型。在游乐场中使用真实的购物者风格的消息进行测试。 </strong><strong>症状：</strong><strong> 该程序在错误的时间使用。 </strong><strong>可能的原因：</strong><strong>“何时使用此过程”太宽泛，或者与另一个过程重叠。 </strong><strong>修复：</strong><strong> 缩小“何时使用此程序”的范围。指出该过程</strong>不<strong>处理的内容。检查其他过程是否应该处理这些请求。 </strong><strong>症状：</strong><strong> 该程序不使用其工具。 </strong><strong>可能的原因：</strong><strong> 未连接工具，或者“如何响应”未按正确的步骤插入工具。 </strong><strong>修复：</strong><strong> 确认该工具已附加到程序中。在“如何响应”中，输入“/”并将工具插入到应运行的步骤。 </strong><strong>症状：</strong></em>* 该过程忽略“如何响应”。</p>
<p><strong><em>*可能的原因：</strong><strong>“如何回应”太长、矛盾或不清楚。 </strong><strong>修复：</strong></em>* 拧紧它。删除不相关的指导。将其分成带有标题的清晰主题部分。在操场上测试变化。 ## 常见问题解答</p>
<p><strong><em>*完全自定义的过程可以使用客户代理附带的工具吗？</strong></em>*</p>
<p>是的。将任何工具附加到您的程序中。 <strong><em>*如何禁用程序？</strong></em>*</p>
<p>在“程序”页面上关闭该程序。您可以随时重新启用它。这适用于客户代理附带的过程和您构建的完全自定义的过程。 <strong><em>*我如何监控我的手术的执行情况？</strong></em>*</p>
<p>绩效仪表板按程序细分解决方案。有关详细信息，请参阅了解性能仪表板。 ## 后续步骤</p>
